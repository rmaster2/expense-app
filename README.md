# 경비청구 시험판 (v0.1)

휴대폰으로 영수증을 찍어 경비 내역을 기록하는 프로그램입니다.
**혼자 쓰면서 검증하는 시험판**이며, 전 직원용이 아닙니다.

---

## 이 시험판으로 확인하려는 것

기능을 쓰려고 만든 것이 아니라, **다음 네 가지가 되는지 확인하려고** 만들었습니다.
이게 안 되면 뒤에 무엇을 만들어도 소용이 없습니다.

| 확인할 것 | 왜 중요한가 |
|---|---|
| 휴대폰에서 카메라가 제대로 열리는가 | 안 되면 촬영 방식 자체를 바꿔야 합니다 |
| 영수증 40장을 담아도 저장 공간이 버티는가 | 용량 한계를 알아야 사진 화질을 정할 수 있습니다 |
| **한 달 뒤에 열어도 자료가 남아 있는가** | 경비 정리는 월 1회 업무라 가장 중요합니다 |
| 홈 화면에 추가하면 앱처럼 열리는가 | 전 직원 배포 방식이 여기서 갈립니다 |

---

## 준비물

- GitHub 계정 (없으면 아래 1단계에서 만듭니다. 무료입니다)
- 컴퓨터 (파일을 올릴 때만 씁니다)
- 안드로이드 휴대폰

---

## 1단계 · GitHub 계정 만들기

이미 계정이 있으시면 2단계로 넘어가십시오.

1. 컴퓨터에서 `github.com` 에 접속합니다.
2. 오른쪽 위 **Sign up** 을 누릅니다.
3. 이메일, 비밀번호, 사용자 이름(영문)을 입력합니다.
   - 사용자 이름은 나중에 주소에 들어갑니다. 예를 들어 `namkim` 으로 정하면
     주소가 `namkim.github.io/...` 가 됩니다.
4. 이메일로 온 인증 번호를 입력하면 끝입니다.

---

## 2단계 · 저장소 만들기

저장소(Repository)는 **파일을 넣어두는 폴더**라고 생각하시면 됩니다.

1. 로그인한 상태에서 오른쪽 위 **＋** → **New repository** 를 누릅니다.
2. **Repository name** 에 `expense-app` 이라고 입력합니다.
3. **Public** 을 선택합니다.
   - 무료로 쓰려면 공개여야 합니다. 이 시험판에는 회사 이름도 직원 이름도
     들어 있지 않으므로 공개해도 문제가 없습니다.
4. 아래 **Create repository** 를 누릅니다.

---

## 3단계 · 파일 올리기

1. 방금 만든 저장소 화면에서 **uploading an existing file** 이라는 파란 글씨를 누릅니다.
   - 안 보이면 **Add file** → **Upload files** 를 누르셔도 됩니다.
2. 받으신 파일 **6개를 전부** 끌어다 놓습니다.

   ```
   index.html
   config.js
   manifest.json
   sw.js
   icon-192.png
   icon-512.png
   ```

   > **주의** — 폴더째로 올리지 마시고, 폴더를 열어서 **파일들만** 올리셔야 합니다.
   > 폴더째 올리면 주소가 한 단계 깊어져서 화면이 열리지 않습니다.

3. 아래 초록색 **Commit changes** 를 누릅니다.

---

## 4단계 · 인터넷 주소 만들기 (GitHub Pages)

1. 저장소 위쪽 **Settings** 를 누릅니다.
2. 왼쪽 목록에서 **Pages** 를 누릅니다.
3. **Branch** 항목의 드롭다운에서 `main` 을 고르고, 옆은 `/ (root)` 그대로 둔 뒤 **Save** 를 누릅니다.
4. **1~2분 기다립니다.** 그 뒤 새로고침하면 화면 위쪽에 주소가 나타납니다.

   ```
   https://사용자이름.github.io/expense-app/
   ```

5. 이 주소를 컴퓨터 브라우저에서 먼저 열어 화면이 나오는지 확인하십시오.

> 주소가 안 열리고 404가 뜨면, 대개 3단계에서 파일이 아니라 폴더를 올린 경우입니다.
> 저장소 첫 화면에 `index.html` 이 바로 보여야 정상입니다.

---

## 5단계 · 휴대폰에 앱처럼 설치하기

1. 위 주소를 휴대폰 **크롬**으로 엽니다.
   - 카카오톡 나에게 보내기로 주소를 보내면 편합니다.
2. 오른쪽 위 **⋮** (점 세 개) 를 누릅니다.
3. **홈 화면에 추가** 를 누릅니다.
4. 홈 화면에 생긴 아이콘으로 여십시오.

> **반드시 홈 화면 아이콘으로 쓰십시오.**
> 브라우저 탭으로 쓰면 자료가 지워질 수 있습니다.

---

## 6단계 · 데이터 보호 켜기

1. 앱을 열고 오른쪽 위 **⚙** 를 누릅니다.
2. **데이터 보호 설정** 이 `켜짐 (안전)` 인지 확인합니다.
3. `꺼짐` 이면 아래 **데이터 보호 켜기** 버튼을 누릅니다.

이 설정을 켜면 휴대폰이 저장 공간을 정리할 때 이 앱의 자료를 건드리지 않습니다.

---

## 사용법

- **＋ 영수증 추가** → 촬영 → 금액 입력 → 저장. 이게 전부입니다.
- 금액만 넣으면 저장됩니다. 나머지는 비워도 됩니다.
- 목록에서 항목을 누르면 수정하거나 지울 수 있습니다.
- 위쪽 **‹ ›** 로 달을 옮깁니다.
- 사진 없이 저장해도 됩니다. (통행료 자동정산처럼 영수증이 없는 경우)

## 영수증이 많을 때 다음 장 위/좌/우/아래 여백이 없던 문제 수정 (v0.9.6)

한 달 치를 전부 입력해 보신 뒤, 영수증이 많은 과목(식대비 19건 등)에서 표 아래
영수증들이 이어지는 페이지로 넘어갈 때 **위쪽 여백 없이 종이 맨 위에 바짝 붙어
찍히는** 문제를 보내주셨습니다. 확인해 보니 여백을 주는 방식 자체에 구멍이 있었습니다.

- 지금까지는 "표지/출금전표/차량운행" 한 장 한 장의 맨 위에 여백을 넣는 방식이었습니다.
  즉 그 블록이 시작되는 첫 장에서만 여백이 생기고, **영수증이 많아 그 블록 안에서
  종이가 자연스럽게 넘어가는 경우**에는 이어지는 장에 여백을 넣는 장치가 없었습니다.
  보내주신 사진이 정확히 이 "이어지는 장"이었습니다.
- 이제는 여백을 종이 자체(인쇄 규격)에 지정하는 방식으로 바꿨습니다. 이렇게 하면
  표지든 출금전표든 이어지는 장이든 상관없이 **찍히는 모든 장에 위/아래/좌/우
  여백이 똑같이 적용**됩니다. 값은 위·아래 12mm, 좌·우 16mm로, 그동안 넓혀 두었던
  좌우 여백 폭은 그대로 유지했습니다.
- 표지/출금전표/차량운행 각 장의 폭과 높이 계산도 이 새 여백 기준에 맞춰 다시 잡았습니다.

이 부분 말고는 표지·출금전표·합계·A4 크기 모두 의도한 대로 나왔다고 확인해 주셨습니다.

## PDF 파일명 지정 + 인쇄물에 안내문이 찍히던 문제 수정 (v0.9.5)

실제로 만들어진 PDF를 보내주셔서 두 가지를 반영했습니다.

### 1. PDF 파일명을 원하는 형식으로

`○○-2026년07월 경비청구-홍길동.pdf` 형식으로 저장됩니다.

- 휴대폰·컴퓨터의 "PDF로 저장" 기능은 **화면 제목을 그대로 파일 이름으로** 씁니다.
  그래서 인쇄 직전에 제목을 이 형식으로 바꿔 두도록 했습니다.
- 앞에 붙일 표시(회사 약칭 등)는 **설정 → 제출자 정보**에 새로 생긴
  **"파일명 앞에 붙일 표시"** 칸에 한 번 입력해 주시면 됩니다. 입력하는 대로
  바로 아래에 완성될 파일명이 미리 보입니다.
- 이 값을 `config.js`(공개되는 프로그램 파일)에 넣지 않고 설정 화면에서 받는 이유는,
  회사 약칭도 회사를 알 수 있는 정보라 공개 저장소에 올리지 않기로 한 원칙 때문입니다.
  이 값은 이사님 휴대폰에만 저장됩니다.
- 관리부 제출 파일(JSON)도 같은 이름 규칙을 쓰게 맞췄습니다. 관리부에서 인쇄물과
  제출 파일을 짝지어 보기 쉬워집니다.

### 2. 인쇄물에 화면용 안내문이 찍히던 문제

보내주신 PDF 2쪽 아래에 "인쇄 화면이 열리지 않거나 백지로 나오면…"이라는 안내문과
버튼이 그대로 찍혀 있었습니다. 화면에서만 보여야 하는 부분인데, 인쇄에서 숨기는
처리를 위쪽 버튼에만 하고 이 부분에 빠뜨린 실수였습니다. 이제 인쇄물에 나오지 않습니다.

> 나머지 부분(표지 1쪽, 출금전표 + 영수증 2쪽, 합계 표시, A4 크기)은 보내주신
> PDF에서 의도한 대로 정확히 나온 것을 확인했습니다.

## 합계 칸에 "합&amp;nbsp;&amp;nbsp;계"로 나오던 문제 수정 (v0.9.4)

**인쇄 백지 문제는 해결된 것으로 보입니다.** 이사님이 보내주신 화면에 표와 영수증
사진이 정상적으로 나왔습니다.

다만 출금전표 합계 칸의 글자가 `합&nbsp;&nbsp;계` 처럼 이상하게 찍히는 문제가
있었습니다. 원인은 이렇습니다.

- 글자 사이를 벌리려고 HTML 기호(`&nbsp;`)를 썼는데, 이 글자가 **보안 처리 함수**를
  한 번 거칩니다. 이 함수는 영수증 상호명 같은 사용자 입력에 이상한 코드가 섞여
  들어오는 것을 막아주는 안전장치인데, HTML 기호까지 "그냥 글자"로 바꿔버립니다.
  그래서 기호가 눈에 보이게 찍힌 것입니다.
- 이 안전장치를 끄는 것은 위험하므로, **기호 대신 진짜 공백문자를 쓰도록** 고쳤습니다.
  이제 "합  계", "총  합  계"로 정상 표시됩니다.
- 같은 실수가 다른 곳에도 있는지 코드 전체를 검사해 확인했습니다(다른 곳은 없었습니다).

## 코드 점검 결과 반영 — 인쇄 방식 재설계 및 여러 오류 수정 (v0.9.3)

이 프로그램을 처음 보는 다른 검토자에게 코드 전체를 다시 점검받고, 지적된 문제를
고쳤습니다. **인쇄 백지의 진짜 원인도 이때 찾았습니다.**

### 인쇄 백지 — 원인을 찾아 방식을 다시 설계했습니다

두 가지가 겹쳐 있었습니다.

1. **설정 화면을 열면 배경 스크롤을 막느라 `overflow:hidden`이 걸리는데, 크롬은
   이 상태의 화면을 인쇄할 때 첫 페이지에서 잘라냅니다.** 인쇄 버튼이 바로 그 설정
   화면 안에 있으니 매번 걸렸던 것입니다. 보고해 주신 "1/1 페이지"가 정확히 이
   증상이었습니다.
2. **사진이 다 그려지기 전에 인쇄가 시작되고 있었습니다.** v0.9.2에 넣은 "0.8초 뒤
   인쇄" 보험 장치가 보험이 아니라 방해물이었습니다. 사진 20~40장은 0.8초 안에
   절대 준비가 안 끝나는데, 그 타이머가 먼저 인쇄를 실행하고 뒤늦게 도착하는
   "준비 완료" 신호는 무시되도록 되어 있었습니다.

그래서 방식을 이렇게 바꿨습니다.

- **인쇄 미리보기 화면이 생겼습니다.** "이번 달 인쇄물 만들기"를 누르면 새 창이
  열리는 대신, **화면이 인쇄물 그 자체로 바뀝니다.** 즉 "인쇄되는 것 = 눈에 보이는 것"
  이라 어긋날 수가 없습니다. 위쪽에 `돌아가기` / `인쇄 / PDF로 저장` 두 버튼이 있습니다.
- **사진이 전부 실제로 그려진 다음에야** 인쇄 버튼이 눌러집니다. 그전까지는 "사진
  준비 중…"으로 표시됩니다. 백지의 직접 원인을 없앤 부분입니다.
- 배경 스크롤 잠금을 인쇄 전에 명시적으로 풀어, 1페이지에서 잘리는 원인을 없앴습니다.
- 새 창(팝업)을 쓰지 않으므로 팝업 차단 문제도 사라졌습니다.
- **혹시 인쇄가 안 될 때를 위한 대비책**으로, 미리보기 화면 아래에 "인쇄물을 파일로
  저장하기" 버튼을 두었습니다. 이 파일을 컴퓨터에서 열어 인쇄하실 수 있습니다.
- 사진을 데이터로 부풀리지 않고 그대로 쓰게 되어(같은 화면이라 가능해졌습니다)
  인쇄물이 훨씬 가벼워졌습니다.
- 영수증 3열 배치도 크롬에서 더 안정적인 방식(그리드)으로 바꿨습니다.

### 함께 고친 것들

- **인쇄물 금액이 안 맞을 수 있던 문제** : `config.js`에서 계정과목 이름을 바꾸거나
  지우면, 과거 내역이 표지 합계에는 남는데 출금전표에는 안 나올 수 있었습니다.
  이제 목록에 없는 과목도 반드시 전표가 만들어집니다. 혹시라도 소계의 합과 전체
  합계가 다르면 인쇄물 첫 장에 빨간 경고가 찍혀 나옵니다.
- **백업에 이름·회사명이 빠져 있던 문제** : 휴대폰을 바꿔 복원하면 인쇄물 만들기가
  곧바로 실패했습니다. 이제 제출자 정보와 설정도 함께 백업/복원됩니다. 복원 속도도
  빨라졌습니다(미리보기 사진을 다시 만들지 않습니다).
- **영수증이 20건을 넘는 계정과목** : 예전에는 영수증이 전부 마지막 장 뒤로 몰려
  번호 대조가 불편했습니다. 이제 그 장에 실린 항목의 영수증만 그 표 아래에 붙습니다.
- **사진이 사라진 경우** 회전·보정·자동읽기 버튼이 아무 안내 없이 조용히 멈추던
  문제를 고쳤습니다.
- **사각 보정 중 뒤로가기를 누르면** 보정한 사진이 사라질 수 있던 문제를 고쳤습니다.
- **운행 기록 날짜를 이미 기록이 있는 날로 바꾸면** 조용히 덮어써지던 문제 →
  이제 먼저 물어봅니다.
- **다른 탭에서 앱이 열려 있으면** 앱이 아무 안내 없이 영구히 멈출 수 있던 문제를
  고쳤습니다.
- **인터넷이 잠깐 끊겼을 때** 그 뒤로 계속 예비 인식기만 쓰던 문제 → 다시 시도합니다.

  정확히 반영했습니다("내역과 사진 전부 지우기").
- **공개 저장소 규칙 위반을 정리했습니다.** 회사 실명(입력란 예시)과 사내 서식번호,
  그룹웨어 제품명이 코드와 이 문서에 들어가 있었습니다. 제가 지켜야 한다고 적어둔
  규칙인데 어긴 부분입니다. 전부 일반 표기로 바꿨습니다.
- `sw.js`의 캐시 값을 `config.js`의 버전과 똑같이 맞추는 방식으로 바꿨습니다
  (`expense-0.9.3`). 두 값이 어긋날 실수를 없애기 위한 것입니다.

> 인쇄 부분은 실제 자료(25건 계정과목 2장 분할, 가로 영수증, 미분류 과목 등)로

## 인쇄물 백지 문제 — 새 창에서 인쇄하는 방식으로 재설계 (v0.9.2)

v0.9.1로 고친 뒤에도 **갤럭시 S24 울트라 + 크롬**에서 여전히 완전 백지(페이지도 1장뿐)로
나온다는 것을 확인해 주셨습니다. "화면 안의 일부만 인쇄되게 다른 부분을 숨긴다"는 방식
자체가 이 화면(사진 촬영·사각보정 등 여러 겹의 화면이 있는 구조)과 잘 맞지 않는 것으로
보여, 방식을 아예 바꿨습니다.

- **이전(v0.9.0~0.9.1)** : 이 화면 안에서 인쇄할 부분만 남기고 나머지를 숨기는 방식.
- **지금(v0.9.2)** : "이번 달 인쇄물 만들기"를 누르면 **완전히 새로운 빈 창**을 열고,
  그 창 안에 지출내역서·출금전표·영수증·차량운행 기록을 처음부터 새로 써 넣은 뒤,
  그 창만 인쇄합니다. 이 화면에 무엇이 열려 있든 전혀 영향을 받지 않는 방식이라
  훨씬 확실합니다.
- 영수증 사진도 이 화면 전용 임시 주소(blob) 대신, 새 창에서도 확실히 보이는 방식
  (데이터 자체를 담는 주소)으로 바꿔 넣습니다.
- 인쇄 버튼을 누르는 즉시(사진을 불러오기 전에) 새 창부터 먼저 엽니다. 나중에 열면
  휴대폰이 "팝업 차단"으로 막을 수 있기 때문입니다. 혹시 새 창이 안 열리면 팝업 차단
  설정을 확인해 달라는 안내가 뜹니다.

> 이번 방식은 실제 데이터로 새 창에 내용이 채워지고 인쇄까지 이어지는 전체 흐름을
> 코드로 재현해 검증했습니다. 다만 갤럭시 S24 울트라 실기기에서의 최종 확인은
> 이사님께 다시 부탁드립니다. 이번에도 문제가 있으면 어느 단계에서 멈추는지
> (새 창 자체가 안 뜨는지 / 창은 뜨는데 내용이 없는지 / 인쇄 버튼을 눌러야만 뜨는지)
> 알려주시면 더 정확히 짚을 수 있습니다.

## 인쇄물이 완전 백지로 나오는 문제 수정 (v0.9.1)

실제 휴대폰에서 확인해 주신 결과 "인쇄 화면은 뜨는데 내용이 아무것도 없고, PDF로
저장해도 백지"였습니다. 원인은 "화면의 이 부분만 인쇄하기"를 만드는 방식에 있었습니다.

- 이전 방식(v0.9.0) : 인쇄할 부분 빼고 나머지를 `display:none`으로 감췄습니다. 이
  방식이 휴대폰 브라우저에 따라 인쇄할 부분까지 같이 감춰 버리는 경우가 있었던
  것으로 보입니다.
- 고친 방식(v0.9.1) : 웹에서 가장 널리 쓰이고 검증된 방식으로 바꿨습니다 - 일단
  전부 안 보이게(`visibility:hidden`) 만든 뒤, 인쇄할 부분만 다시 보이게 하고 그
  부분을 페이지 맨 위로 끌어올리는 방식입니다.
- 추가로, 내용을 채운 직후 곧바로 인쇄를 띄우면 일부 휴대폰에서는 화면이 미처
  그려지기 전이라 백지로 나올 수 있어, 화면이 실제로 그려질 때까지 짧게
  기다렸다가 인쇄를 띄우도록 고쳤습니다.

> 이 문제는 제가 가진 환경에서는 재현해 확인할 수 없어(실제 휴대폰 테스트가
> 필요한 종류의 문제입니다), 웹에서 가장 안정적이라고 알려진 방식으로 교체하는
> 방향으로 고쳤습니다. 이번에도 백지로 나오면, 어느 휴대폰·브라우저인지 알려주시면
> 다시 점검하겠습니다.

## 인쇄물(PDF) 만들기 기능 추가 (v0.9.0)

설정 화면에 **"이번 달 인쇄물 만들기"** 버튼이 새로 생겼습니다. 누르면 지출내역서(표지) ·
출금전표 · 영수증 사진 · 차량운행 기록이 순서대로 이어진 화면이 뜨고, 거기서 브라우저의
인쇄 기능으로 **"PDF로 저장"**을 고르면 파일이 만들어집니다. 그 파일을 사내 전자결재에
첨부하면 됩니다. 유료 프로그램이나 라이브러리는 전혀 쓰지 않았습니다(비용 0원).

**구성 순서**

- 지출내역서(표지) — 상단에만 내용이 들어가고 하단은 비웁니다. 결재란은 넣지 않았습니다
  (전자결재로 제출하므로 사내 결재선이 그 역할을 대신합니다).
- 출금전표 — 계정과목별로 나뉩니다. **9건 이하는 절반 크기**(기존 PC용 전표 서식과 같은 기준),
  **9건을 넘으면 전체 크기**로 커집니다. 열은 번호 · 날짜 · 적요 · 지출처 · 금액 순서이고,
  적요가 가장 넓습니다(번호2 : 날짜4 : 적요20 : 지출처8 : 금액10 비율). 표가 끝나는 지점
  바로 아래부터 영수증이 이어집니다(절반/전체 상관없이 동일).
- 영수증 — 사진마다 길이가 다른 점을 살려 3열로 빽빽하게 배치합니다(원본 비율 그대로,
  글자가 작아지지 않도록 유지). 가로로 넓은 영수증은 3등분하지 않고 한 줄 전체를 씁니다.
  각 사진과 위 출금전표 표에 같은 번호를 매겨 대조하기 쉽게 했습니다.
- 차량운행일지 — 이번 달 전체를 A4 한 장에 담습니다(기존과 동일한 구성).

**영수증이 유독 긴 경우(예: 주유비)는 어떻게 되나요** — 항목 개수만 보고 크기를 정하지
않습니다. 페이지를 미리 잘라서 만들지 않고, 문서를 죽 이어 쓴 뒤 "여기서부터는 새 장"
정도만 지정해 두는 방식으로 만들었습니다. 그래서 영수증이 그 페이지에 다 들어가지 않으면
브라우저가 알아서 다음 장으로 자연스럽게 넘겨줍니다. 미리 계산해서 자르는 방식보다 더
정확하고 안정적입니다.

**확인해 주셔야 할 것**

- 설정 화면의 "제출자 정보"에 **회사명** 입력란이 새로 생겼습니다. 인쇄물 표지에 표시되며,
  이 휴대폰에만 저장됩니다(공개된 프로그램 코드에는 들어가지 않습니다).
- 실제 여러 달치 데이터로 한 번 인쇄해 보시고, 페이지가 넘어가는 지점이나 글자 크기가
  괜찮은지 확인 부탁드립니다. 특히 영수증이 아주 많이 쌓인 달(예: 20건 넘는 계정과목)은
  아직 실제로 테스트해보지 못했습니다.

## 두 번째 영수증부터 인식이 나빠지는 문제 수정 (v0.7.2)

**원인을 찾았습니다 — 짐작하신 대로 프로그램 안에 이전 결과가 남아있던 것이 맞았습니다.**
"사진에서 자동으로 읽기"에 쓰는 인식 엔진(PaddleOCR)이 내부적으로 사진마다 결과를
자체 캐시에 저장해 두는데, 그 캐시를 구분하는 값(키)을 사진 파일 앞부분 1KB의
해시값과 전체 용량만으로 만듭니다. 저희 앱은 모든 영수증 사진을 같은 크기·화질로
압축해서 저장하기 때문에, 서로 다른 두 영수증이라도 파일 앞부분(사진 내용과 무관한
고정 헤더 부분)이 우연히 같아지는 경우가 흔했습니다. 그 결과 두 번째 영수증부터는
실제로 다시 읽지 않고 **첫 번째 영수증의 예전 인식 결과를 그대로 돌려주는** 사고가
났던 것입니다. 이 캐시를 아예 쓰지 않도록 꺼서, 매번 사진을 새로 읽도록 고쳤습니다.

> 알려주신 "화면에 이전 사진이 남아있는데 프로그램은 없다고 생각한다"는 증상은
> 코드를 다시 살펴봤지만 이번엔 그 원인을 확실히 짚어내지 못했습니다. 위 수정 이후에도
> 같은 증상이 다시 보이면, 어느 시점에(새 영수증 추가 직후인지, 사각 보정 화면에서인지,
> 자동 읽기 버튼을 누른 직후인지) 나타나는지 알려주시면 다시 점검하겠습니다.

## 사각 보정 오류 수정 (v0.7.1)

실제로 써보시고 알려주신 문제 세 가지를 고쳤습니다.

- **하단 모서리 점을 조정할 수 없던 문제**: 화면을 아래로 스크롤하지 못해 세로로
  긴 영수증의 아래쪽 모서리에 손이 닿지 않던 문제를 고쳤습니다. 이제 손가락으로
  화면을 스크롤해 아래쪽 모서리도 조정할 수 있습니다.
- **적용하면 바로 메인 화면으로 나가버리던 문제**: "적용"을 누르면 입력 화면까지
  같이 닫혀 방금 보정한 사진이 사라지던 문제를 고쳤습니다. 이제 "적용" 후에는
  보정된 사진이 반영된 입력 화면으로 정상적으로 돌아옵니다.
- **"사진에서 자동으로 읽기"가 사진을 다시 찍으라고 하던 문제**: 위 문제 때문에
  방금 찍거나 보정한 사진 정보가 지워져서 생긴 문제였습니다. 함께 고쳐졌습니다.

## 영수증 사각 보정 - 배경 없이 영수증만 저장 (v0.7)

촬영하거나 앨범에서 고른 사진에서, 영수증의 네 모서리를 손으로 직접 맞춰
기울어짐을 펴고 배경을 없앨 수 있습니다.

1. 사진을 촬영하거나 앨범에서 고릅니다
2. 사진 아래 새로 생긴 **사각 보정** 버튼을 누릅니다
3. 영수증의 네 모서리에 있는 주황색 점을 손끝으로 끌어, 실제 영수증
   모서리에 맞춥니다
4. 위쪽 **적용**을 누르면 배경이 사라지고 영수증만 평평하게 펴져 저장됩니다

> **완전히 선택 사항입니다.** 그냥 두면(점을 옮기지 않으면) 사진 전체가 그대로
> 저장되며, 이 화면 자체를 안 써도 지금까지와 똑같이 쓸 수 있습니다.
> **취소**를 누르면 원래 사진 그대로 남습니다.

**참고**: 처음에는 카메라가 찍을 때 자동으로 영수증 모서리를 찾아주는
방식(삼성 카메라의 "문서" 모드와 같은 방식)도 검토했습니다. 무료로 구할 수
있는 오픈소스 라이브러리(jscanify)로 실제 영수증 사진 두 장을 시험해 봤지만,
배경과 대비가 약할 때 엉뚱한 부분을 잘라내는 경우가 많아 믿고 쓰기 어려웠습니다.
그래서 자동 인식 없이, 손으로 네 모서리를 맞추는 지금의 방식을 택했습니다.
그 대신 별도의 무거운 라이브러리(수 MB 이상)를 전혀 쓰지 않아 가볍습니다.

## 자동 채우기 오류 수정 (v0.6.1)

v0.6에서 인식 엔진을 바꾸면서 생긴 문제 세 가지를 고쳤습니다. ("국수명가" 영수증에서
금액이 5억 넘게 채워지고, 날짜가 다른 날로 잘못 채워지고, 지출처에 사업자번호와 주소까지
길게 붙던 문제입니다.)

- **금액이 엉뚱하게 큰 숫자로 채워지는 문제**: 두 개의 서로 다른 숫자가 공백만으로 붙어
  하나의 큰 숫자로 잘못 합쳐지던 문제를 고쳤습니다. 경비 한 건이 억 단위를 넘는 경우는
  없으므로, 이제 8자리(9,999만원)를 넘는 값이 나오면 잘못 합쳐졌다고 보고 **비워 둡니다**.
- **날짜가 다른 날로 채워지는 문제**: "거래일시" 처럼 실제 사용일을 뜻하는 라벨이 붙은
  날짜를 최우선으로 보도록 고쳤습니다. 사업자등록일 등 다른 날짜가 영수증 위쪽에 먼저
  나오면 그걸 잘못 집는 문제가 있었습니다.
- **지출처에 사업자번호·주소까지 길게 붙는 문제**: "[매장명] 국수명가 [사업자] ..." 처럼
  태그를 대괄호로 감싸는 영수증 형식에서, 상호명 뒤로 다음 태그까지 전부 잡히던 문제를
  고쳤습니다. 이제 다음 "[" 태그 앞에서 멈춥니다.

> 여전히 이상하게 채워지는 영수증이 있으면, 인식된 글자(붙여넣기 칸에 남아 있는 내용)를
> 그대로 알려주십시오.

## 영수증 인식 엔진 교체 (v0.6)

영수증 사진을 읽는 엔진을 한글 전용 인식 엔진(PaddleOCR)으로 바꿨습니다.

- 기존 방식(Tesseract)보다 특히 **금액 숫자**를 훨씬 정확하게 읽습니다. 실제 영수증 두 장으로
  비교해 본 결과, 금액·부가세·합계 숫자가 전부 정확하게 나왔습니다.
- 이 엔진도 무료이며, 사진을 서버로 보내지 않고 휴대폰(브라우저) 안에서만 처리합니다. 유료
  OCR API는 여전히 쓰지 않습니다.
- 처음 한 번만 인식 모델을 받는 데 몇 초 더 걸릴 수 있습니다(인터넷 필요). 받아온 모델은
  브라우저에 남아, 그 다음부터는 다시 받지 않습니다.
- 혹시 회사 네트워크가 특정 주소를 막고 있어 새 엔진을 못 받아오면, 자동으로 예전 방식
  (Tesseract)으로 바뀌어 인식 기능 자체는 계속 동작합니다. 어떤 방식으로 인식했는지는
  설정 화면(⚙) → **프로그램 정보** → **글자 인식 엔진** 에서 확인할 수 있습니다.
- 상호명처럼 장식적인 글자는 여전히 한두 글자 정도 틀릴 수 있습니다. 금액·날짜처럼 중요한
  값은 항상 확인 후 저장하십시오.

## 자동 채우기 오류 수정 (v0.5)

실제로 써보시고 알려주신 문제 두 가지를 고쳤습니다.

- **금액이 잘리는 문제**: "128,000"처럼 숫자 사이에 OCR이 공백을 넣는 경우(예: "128, 000") 앞부분("128")만
  잡히던 문제를 고쳤습니다.
- **지출처에 주소가 들어가는 문제**: 상호명 라벨이 없는 영수증에서 주소 줄을 상호명으로 잘못 채우던 문제를
  고쳤습니다. 이제 주소처럼 보이는 줄은 건너뛰고, 그래도 확실한 후보가 없으면 **비워 둡니다**(틀린 값을
  자동으로 채우는 것보다 안전하다고 판단했습니다).
- 계정과목은 여전히 직접 선택하셔야 합니다 — 영수증 글자만으로는 정확히 구분하기 어려워 자동화하지 않았습니다.

> 여전히 이상하게 채워지는 영수증이 있으면, 인식된 글자(붙여넣기 칸에 남아 있는 내용)를 그대로 알려주십시오.

## 영수증 글자 자동 채우기 (v0.4에서 개선됨)

처음에는 사진을 길게 눌러 텍스트를 복사하는 방식(v0.3)으로 만들었는데, 실제로 써보니
안드로이드/브라우저에 따라 그 메뉴 자체가 안 뜨는 경우가 있어(사진이 갤러리가 아니라
웹페이지 안에 떠 있기 때문입니다), v0.4부터는 **앱이 사진을 직접 읽는 방식**으로 바꿨습니다.
유료 OCR API는 여전히 쓰지 않습니다(무료 인식 프로그램을 그 자리에서 내려받아 씁니다).

1. 영수증을 촬영하거나 앨범에서 고릅니다
2. 입력 화면의 **사진에서 자동으로 읽기** 버튼을 누릅니다
   - 처음 한 번은 인식 프로그램을 받느라 몇 초~십몇 초 더 걸릴 수 있습니다 (인터넷 필요)
   - 이후에는 더 빨라집니다
3. 금액·날짜·지출처가 자동으로 채워집니다
4. **채워진 내용은 반드시 확인 후 저장하십시오.** 자동으로 저장되지 않으며, 인식이
   완벽하지 않을 수 있습니다

> 예전처럼 사진을 길게 눌러 복사한 글자를 직접 붙여넣고 **자동 채우기**를 눌러도 됩니다(그대로 남겨뒀습니다).
> 인식이 잘 안 되는 영수증 형식을 발견하시면 알려주십시오. 규칙을 계속 보완할 수 있습니다.

## 관리부 제출 파일 만들기 (v0.2에서 추가됨)

이번 업데이트로 생긴 기능입니다. 매달 마감할 때 이렇게 하시면 됩니다.

1. 제출하려는 달로 이동합니다 (위쪽 **‹ ›**)
2. 오른쪽 위 **⚙** 를 눌러 설정 화면을 엽니다
3. **제출자 정보**에 이름을 한 번만 입력합니다 (다음부터 자동으로 기억합니다)
4. **관리부 제출** 아래 **이번 달 제출 파일 만들기** 버튼을 누릅니다
5. 만들어진 파일(예: `경비제출_홍길동_2026-01.json`)을 사내 전자결재에 첨부해 제출합니다

> 이 파일에는 사진이 들어가지 않습니다. 금액과 적요(지출 내용)만 담겨 있어 용량이 매우 작습니다.
> 백업 파일(사진 포함, 내 휴대폰 복구용)과는 다른 파일이니 헷갈리지 않도록 주의하십시오.

## 한 달 검증 방법

이 시험판의 핵심입니다. 아래대로만 해주시면 됩니다.

1. **오늘** — 앱을 설치하고 영수증 한두 장을 넣습니다.
2. **평소대로** — 결제할 때마다 그 자리에서 찍어 넣습니다.
3. **일주일에 한 번쯤** — ⚙ 화면에서 `사용 중인 용량` 을 확인합니다.
4. **한 달 뒤** — 앱을 열어 **자료가 그대로 남아 있는지** 확인합니다.
   ⚙ 화면의 `경과 일수` 와 `지난번 사용` 을 보면 며칠 만에 열었는지 알 수 있습니다.

**중간에 꼭 한 번은 백업 파일을 내려받아 두십시오.** (⚙ → 백업 파일 내려받기)
자료가 날아가는지 확인하는 시험이라, 실제로 날아갔을 때 되돌릴 수단이 필요합니다.

## 프로그램을 고치고 싶을 때

`config.js` 파일만 고치시면 됩니다. `index.html` 은 건드리지 않으셔도 됩니다.

| 고칠 내용 | 방법 |
|---|---|
| 계정과목 추가·변경 | `categories` 의 목록을 고칩니다 |
| 사진 화질을 높이고 싶다 | `imageQuality` 를 `0.85` 로 올립니다 (용량이 늡니다) |
| 사진 용량을 줄이고 싶다 | `imageMaxSide` 를 `1200` 으로 낮춥니다 |

**고친 파일을 올리는 방법**

1. GitHub 저장소에서 `config.js` 를 누릅니다.
2. 오른쪽 위 **연필 아이콘** 을 누릅니다.
3. 내용을 고칩니다.
4. 아래 **Commit changes** 를 누릅니다.
5. `sw.js` 파일도 열어서 맨 위 `expense-v1` 을 `expense-v2` 로 바꿔주십시오.
   이걸 해야 휴대폰이 옛날 화면을 계속 보여주지 않습니다.
6. 휴대폰에서 앱을 껐다 켜면 바뀐 내용이 적용됩니다.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 화면이 안 열린다 (404) | 파일을 폴더째 올리지 않았는지 확인 |
| 고쳤는데 그대로다 | `sw.js` 의 버전 숫자를 올렸는지 확인 |
| 사진이 옆으로 눕는다 | 사진 아래 **↻** 버튼으로 돌립니다 |
| 저장이 안 된다 | ⚙ 에서 용량이 꽉 찼는지 확인 |
| 자료가 사라졌다 | **바로 알려주십시오.** 이 시험판이 찾으려던 문제입니다 |

## 이 시험판에 없는 기능

일부러 뺐습니다. 검증에 필요 없고, 각각 따로 확인할 사안이기 때문입니다.

- PDF 만들기
- 영수증 대지 배치 (전표 뒤에 영수증을 모아 붙이는 화면)
- 차량운행일지
- 관리부가 여러 명의 제출 파일을 한 번에 모아 자동 합산하는 도구 (제출 파일을 "만드는" 기능은 v0.2에 추가됨. 여러 명 파일을 "모으는" 도구는 아직 없음)
- 전자결재 연동

다만 **자료 구조는 처음부터 위 기능들을 염두에 두고 만들었습니다.**
나중에 기능을 붙일 때 지금 넣은 자료를 그대로 씁니다.
